## Outcome

Slider and RangeSlider gained an opt-in horizontal `appearance="block"`:
labelled capsule, 44×44 hits, small thumbs, atomic fallback, `ltr`/`rtl`
geometry, and forced-color roles. `appearance` is orthogonal to `variant`.
Omission keeps track anatomy and the current value machines.

Vertical block is invalid in Svelte, React, shared Rust, and GPUI. Adapters
throw or panic before paint. Jetstream specimens compile only.

Native specs carry resolved visible strings. `formatVisible*` stays web-only
on the drift allowlist. Visible text never reads `ariaLabel` / `valueText`.

RangeSlider ties choose lower and clamp at the sibling. Pointer, cancel, lost
capture, disablement, and teardown share one `POINTER_END` terminal.

Native block paint puts a full-width 44px scrub surface above the focusable
hits so coincident thumbs still report capsule-relative fractions.

React packed `SliderAppearance` proofs map onto installed `src/types.ts`. The
package `types` condition is the value barrel, which is not tsc-clean.

## Review repair

Orchestrator review
https://github.com/inflatable-cookie/poodle/pull/154#issuecomment-5502785278
caught three holes in the original proof. Repair stayed on
`feature/g16-046-block-sliders` in this worktree.

### Native fit

`paint_slider_block` / `range_slider_block` no longer guess `160px` or
`chars * font * 0.5`. Hosts pass parent-owned capsule span and a measure.
Production GPUI uses a two-pass element in `poodle-gpui-node-backend`: wait for
allocated width, `shape_line` the resolved visible strings, then construct.
That is still architecture 010 (`Spec + RenderContext -> Node`). No new
renderer/layout architecture. Missing layout inputs panic at paint.

Mounted GPUI `block_slider_fit_uses_parent_width_and_shaped_advance`:

- `ABCDEFGH` at 80px parent falls back; at 400px it inlines. Fixed 160px
  cannot do both.
- The GPUI test font is monospace (`WWW` and `iii` both 25.2px at 14px).
  Glyph W vs i cannot discriminate. Shaped `iii` is 25.2px vs heuristic 21px.
  A span whose available fits the heuristic and misses the shaped advance
  falls back.

### Web 44×44

Hits use `pointer-events: auto`, 44×44 boxes, `overflow: visible`, and
`min-height: max(..., 44px)`. Visual capsule/thumb stay size-token sized
(28px at `xs`). Root and hit both scrub; hits `stopPropagation`.

`effigy test:block-slider-hit` (Chromium + WebKit): Slider `xs` and `xs`
compact, RangeSlider both thumbs, Svelte and React. Geometry is
`getBoundingClientRect` plus `elementFromPoint` outside the capsule.
Dispatch is a hit-count increment on pointer down. CSS-string assertions
are not this proof.

Original target plant (`--poodle-slider-block-hit: 24px`) only broke a CSS
substring test. That was not a real-target falsification.

### React teardown

Slider and RangeSlider keep current `onValueChange` / `onValueCommit` /
controlledness on refs. Unmount calls `cancelOnUnmount.current`, which is
the latest `terminate`. `packages/react/components/test/BlockSliderLifecycle.test.tsx`
rerenders callback A→B, including a controlledness swap, then unmounts:
A is silent, B receives 70 / `[40, 80]`.

Original terminal plant only proved one core Slider `POINTER_END`. It did
not prove adapter teardown or RangeSlider.

## Production host height

Exact-head review
https://github.com/inflatable-cookie/poodle/pull/154#issuecomment-5506035660
on `ed816f3ea` while the g16.045 rebase was in flight: production
`request_layout` used `block_*_min_height` (`max(44, capsule)`). Fallback
paints after that surface, so a narrow parent could overlap the next
sibling. The earlier fit test masked it with `min_height = 80.0`.

Repair in this worktree:

- `BlockSliderLayoutHost` / Range twin use `request_measured_layout`.
  Width is parent-owned. Height is the same fit decision: surface only
  when inline; surface plus `text_style.line_height` when fallback.
- Range fallback is `no_wrap`, same as Slider. A wrapping range line was
  ~45px and could not sit in a one-line reservation.
- Mounted
  `block_slider_production_host_height_contains_fallback_and_not_wide_inline`
  uses production `block_*_min_height`, a following 8px sibling, 80px and
  400px. Fallback stays inside the host; the sibling sits below it; wide
  inline height stays the surface.

Not a fixed 80px production height. Immediate-after-capsule fallback
stays. Shaping, 44×44 hits, and React teardown were not reopened.
