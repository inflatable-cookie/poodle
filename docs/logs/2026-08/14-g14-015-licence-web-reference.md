## Public core API

Mirror maps, for the downstream Longhorn assertion:

- `LICENCE_MIRROR_FIELDS` — `{ LicenceSeatProjection: ["machineId", "label", "thisMachine"] }`
- `LICENCE_MIRROR_VARIANT_FIELDS` — `LicenceUsabilityProjection`,
  `LicenceTrustBasisProjection`, `LicenceCredentialProjection`, keyed by
  discriminant, each list carrying its own discriminant

Keys are the authority's protocol type names so a downstream `exact()`-style
comparison against its generated `LICENCE_FIELDS` / `LICENCE_VARIANT_FIELDS`
needs no reshaping. **That cross-repo gate does not exist yet.** This PR ships
the half Poodle owns; the assertion is g14.016's, in the Longhorn adapter.

Deliberately absent, per the card: no wire record for the flattened controller
reads (`usable`, `attention`, `useUntil`, `updateUntil`) — Longhorn has none,
and inventing one would assert a shape that is not there. No unrelated
`HeldLicence` fields either.

View and resolution API: `licenceStatusView`, `resolveLicenceSubmit`,
`licenceKeyProblemMessage`, `licenceMachineLabel`, `licenceFileContentsBase64`,
`licenceSeatRows`, `licenceOtherSeats`, `LICENCE_ROUTES`, and the six message
constants.

## Decisions worth keeping

**Too-short is checked before the typo predicate.** The contract demands the
two messages stay distinct *and* that `isProbablyATypo() === true` yields typo
copy. Longhorn answers `false` for a truncation, so the order changes nothing
today; it closes the case where an unusual host predicate would collapse the
two. Pinned by `a host predicate that claims a truncation is a typo…`.

**The emitted key is the raw one, not the parser's normalized form.** `parse`
saying yes is the whole of Poodle's business with it. Re-emitting the parser's
output would be Poodle deciding the credential's spelling.

**`attention` cannot make an actionable state calm, or a calm state loud.** The
state picks the tone; `informational` may only lift neutral to info. That is
what keeps `inGrace` out of warning tokens under every attention value.

**Focus goes to the route panel's first focusable, via `getFocusableElements`.**
Neither `TextInput` exposes a usable imperative handle in both frameworks
(Svelte's `focus()` is not exported), so a shared core helper against the panel
element is the one mechanism both shells can run. It satisfies both contract
clauses — first field on route activation, relevant field on invalid submit —
because in every route the relevant field *is* the first focusable.

**Two buttons on the account route.** The anatomy puts "Continue with account"
inside the panel and `Activate` outside it, shared by all routes. Both run the
same submit path. Implemented literally rather than hiding one; a route whose
submit lives somewhere else is the kind of asymmetry the card exists to prevent.

## Contract edits (discovered contradiction)

`licence-activation.md` and `licence-seats.md` titled section 4
`Public Props And Events`, which matches neither drift gate's heading pattern:
`contract-prop-drift` looks for `### Public Props`, and `contract-callback-drift`
for a `Callbacks`/`Events` heading. As written, both components would have
shipped with `onActivate` / `onRelease` undocumented as far as the gates are
concerned — the exact hole `contract-callback-drift` was built to close after
`onDeleteContinuation`. Restructured to `## 4. Props And Events` with
`### Public Props` and `### Callbacks` sub-headings, following `settings-shell`.
`licence-status.md` got the same treatment (`## 4. Props And Inputs`) so its
props are gated too. No prop, default, type, or semantic changed.
