# 0.4.2 — 2026-09-14

`0.4.2` repairs the published Svelte Tabs cross-window transfer regression in
`0.4.1` and carries the remaining compatible consumer-sweep fixes. It has no
breaking API change.

## Public-intent fixes

- Svelte Tabs forwards `crossWindowSourceBridge` from the Tabs parent to every
  eligible TabsItem again. Pointer pre-drag now invokes host preparation once
  with the selected tab source identity. The packed-package consumer fixture
  proves the compiled archive preserves the bridge.
- The shared DOM drag controller treats `role="slider"` as interactive, so
  Slider, RangeSlider, fader, and other slider-role gestures do not initiate an
  ancestor drag source.
- Svelte and React MenuSurface items use their required visible `item.label` as
  an exact explicit accessible name. Action, checkbox, radio, disabled, and
  submenu-parent rows inherit the rule; separators remain structural.
- The npm release workflow publishes the certified local tarballs through
  explicit relative paths and uses a bounded registry-availability check after
  trusted publication.

## Downstream checks

- Re-run cross-window Svelte tab transfer through the public package. The host
  bridge must prepare once and transfer state must no longer remain idle.
- Recheck faders or other slider-role controls nested inside draggable rows;
  their pointer gesture must stay with the control.
- Recheck Menu and ContextMenu semantic serialization where descendant text is
  not used as a fallback accessible name.
