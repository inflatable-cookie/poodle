# 0.4.16 — 2026-11-26

Coordinated npm/web and native maintenance release under `v0.4.16`, cut for
Longhorn's two explicit update states. Additive for web consumers except two
unused Iceberg-specific CSS recipe hooks noted below. **The experimental `quiet`
rendering style is opt-in only; the default look does not change.**

The release includes the entire range after `v0.4.15`, through
`e8a83ebf5082a289432353675865834ded2ca62c`.

## Changes

### Longhorn update states (additive, public-intent entry points)

- **`unavailableForTarget` availability state.** `UpdateAvailabilityProjection`
  gains `{ state: "unavailableForTarget"; version: string }` (Rust:
  `UpdateAvailabilityProjection::UnavailableForTarget { version }`). When the
  channel has a release with no artifact for the host system, `UpdateStatus`
  renders an informational state ("No update for this system") with no action
  and suppresses notices.
- **`malformedArtifact` invalid-artifact state.** `UpdateRejectionCode` gains
  `malformedArtifact` (Rust: `UpdateRejectionCode::MalformedArtifact`), paired
  with `lastRejectionDetail` (Rust: `last_rejection_detail` /
  `with_last_rejection_detail`) on `UpdateStatus` and `UpdateCenter`. It renders
  as the warning-toned `invalidArtifact` state (Rust:
  `UpdateStatusViewState::InvalidArtifact`), shows the authority's installer
  detail as its body, and offers a single `downloadAgain` action (Rust:
  `UpdateAction::DownloadAgain`) emitted as `onDownloadAgain` with label
  `downloadAgainLabel` (Rust: `download_again_label` /
  `with_download_again_label`).
- Both additions are additive across `@inflatable-cookie/poodle-core`,
  `@inflatable-cookie/poodle-svelte`, `@inflatable-cookie/poodle-react`,
  `poodle-headless`, `poodle-specs` and `poodle-render`. Existing hosts keep
  working and gain both states when the update authority reports them.

### Rendering style groundwork (additive, opt-in only)

- **Experimental `quiet` style.** Introduces the `data-style` axis and new CSS
  token entry points (`@inflatable-cookie/poodle-core/tokens/css/poodle-styles.css`,
  `./tokens/style-default.css`, `./tokens/style-quiet.css`), plus fill, surface
  and selection treatments across the component library and neutral/selection
  colour roles. **`quiet` is experimental and opt-in; without opting into
  `data-style="quiet"`, the default look does not change.**
- **Type roles and font overrides.** Adds typography roles across the six proof
  components with documented font override order in
  `docs/guides/svelte-developer-guide.md` (`--poodle-font-sans` /
  `--poodle-font-mono` apply after component recipes and before per-role family
  tokens while preserving subtree and legacy per-role overrides).

### Behaviour, theme resolver and Svelte skill (additive)

- **Portable active-option and selection policies.** Exports
  `moveActiveOption`, `reconcileActiveOption` and `selectionTransition` from
  `@inflatable-cookie/poodle-core`, names the supported behaviour subset, and
  ships a tag combobox recipe.
- **Shared theme resolver.** Ports the preview theme resolver
  (`theme-resolver`, `themePresets`, `previewThemeCssProperties`) to
  `@inflatable-cookie/poodle-core` and `poodle-headless`.
- **Installable Svelte implementer skill.** Ships `skills/poodle` with its
  generated reference checked by `docs:lint`, updates the Svelte quick-start
  theme comment to point at the full generated theme set, and includes
  `llms.txt` in `@inflatable-cookie/poodle-core`.

### Native groundwork and removals

- **Conformance kit pilot and shared specimens.** Adds internal crates
  `poodle-conformance` (headless fixtures, receipts and GPUI runner) and
  `poodle-specimens` (shared backend-neutral specimens).
- **Removed: legacy Jetstream direct renderer.** Removed the legacy Jetstream
  direct renderer; native crates have no external consumer.
- **Removed: two unused Iceberg CSS recipe hooks.** Removed
  `--poodle-recipe-card-theme-iceberg-elevated-shadow` and
  `--poodle-recipe-metric-tile-theme-iceberg-fill`. No consumer reads them;
  callers with custom overrides targeting either variable should remove them.
- Root, core, Svelte, private React and all Rust crate versions move together to
  `0.4.16`. Svelte and React require core `>=0.4.16 <0.5`. Existing peer ranges
  remain.
