# 0.4.0 — 2026-09-12

`0.4.0` is the Poodle preview-channel release candidate prepared from the
accepted post-`g18.026` main line. It is not yet tagged or published; the
candidate is certified and merged first, then `g18.009` owns tagging,
publication and the Desktop return.

This pre-1.0 minor carries one large breaking presentation change (Slider and
RangeSlider), one safe-by-default markdown change, and the accumulated additive
web editor surface (`./editor`, `./rich-text`, `MarkdownRenderer`). Consumers
must read this note before adopting the release.

The accepted classification of every public delta since immutable `v0.3.0`
lives in
[`docs/evidence/releases/g18-027-v040-public-surface-delta.md`](../evidence/releases/g18-027-v040-public-surface-delta.md).
It is the migration source for this note.

## Public-intent delta since v0.3.0

### Breaking — Slider and RangeSlider presentation

Slider and RangeSlider present one control. `variant="block"` is the default
capsule; `variant="embedded"` is the dense track-and-thumb alternative. The
pre-0.4 `appearance` prop, `variant="standard"`, the fallback-text helpers, and
the combined `formatVisibleRange` string are removed with no aliases. Vertical
block presentation is supported in every runtime.

| Surface | Removed / changed | Migration |
| --- | --- | --- |
| Svelte `Slider.appearance` | `"track" \| "block"`, default `"track"` | Remove the prop. `variant="embedded"` is the dense track control; `variant="block"` (default) is the capsule. |
| Svelte `Slider.variant` | `"standard" \| "embedded"`, default `"standard"` → `"block" \| "embedded"`, default `"block"` | `"standard"` has no alias: pass `variant="embedded"` for the old dense control, or omit for the new block default. |
| Svelte `RangeSlider.appearance` | `"track" \| "block"`, default `"track"` | Same as Slider. |
| Svelte `RangeSlider.variant` | `"standard" \| "embedded"`, default `"standard"` → `"block" \| "embedded"`, default `"block"` | Same as Slider. |
| Svelte `RangeSlider.formatVisibleRange` | removed | Block always paints lower/upper endpoint values at their scale anchors; use `formatVisibleValue` per thumb for custom text. |
| Packed React `Slider.appearance`, `RangeSlider.appearance` | removed | Mirror the Svelte migration. |
| Packed React `RangeSlider.formatVisibleRange` | removed | Mirror the Svelte migration. |
| Core/Svelte type `SliderAppearance` (also `./types`) | `"track" \| "block"` | Replaced by `SliderVariant`; `SliderPolarity` is exported too. |
| Core helper `assertHorizontalBlockAppearance` | removed | Vertical block is valid in every runtime; drop the guard. |
| Core helpers `sliderFallbackText`, `rangeSliderFallbackText`, `defaultVisibleRangeText`, `resolveRangeVisibleRange` | removed | The external fallback line and combined range text are gone. Block text stays inside the capsule and the optional label yields under narrow fit. |
| Core type `TabsState` | removed | Replaced by the narrower `TabsPin`. |
| Core type `TabsTooltipEffect` | removed | The tooltip sub-machine stays adapter-side; no public effect type is exported. |
| Slider `data-appearance="block"` root attribute | renamed to `data-variant="block"` | Update consumer CSS selectors; `data-variant` now carries `block`/`embedded`. |

### Breaking — Slider-family recipe hooks

Eighteen documented recipe hooks are no longer read. Slider and RangeSlider now
share one family foundation that reads the `--poodle-recipe-slider-*` names for
both components, so overrides on the removed RangeSlider names silently stop
applying.

| Removed hook | Successor |
| --- | --- |
| `--poodle-recipe-slider-block-fallback-text` | none; no external fallback line exists |
| `--poodle-recipe-slider-control-thumb-fill` | `--poodle-recipe-slider-control-fill` |
| `--poodle-recipe-slider-control-shadow` | none |
| `--poodle-recipe-slider-focus-control-shadow` | `--poodle-recipe-slider-focus-ring` |
| `--poodle-recipe-range-slider-track-fill` | `--poodle-recipe-slider-track-fill` |
| `--poodle-recipe-range-slider-track-border` | `--poodle-recipe-slider-track-border` |
| `--poodle-recipe-range-slider-center-fill` | `--poodle-recipe-slider-center-fill` |
| `--poodle-recipe-range-slider-control-fill` | `--poodle-recipe-slider-control-fill` |
| `--poodle-recipe-range-slider-control-thumb-fill` | `--poodle-recipe-slider-control-fill` |
| `--poodle-recipe-range-slider-control-track-fill` | none |
| `--poodle-recipe-range-slider-control-thumb-shadow` | none |
| `--poodle-recipe-range-slider-focus-control-thumb-shadow` | `--poodle-recipe-slider-focus-ring` |
| `--poodle-recipe-range-slider-block-remainder-fill` | `--poodle-recipe-slider-block-remainder-fill` |
| `--poodle-recipe-range-slider-block-remainder-text` | `--poodle-recipe-slider-block-remainder-text` |
| `--poodle-recipe-range-slider-block-handle-fill` | `--poodle-recipe-slider-block-handle-fill` |
| `--poodle-recipe-range-slider-block-handle-border` | `--poodle-recipe-slider-block-handle-border` |
| `--poodle-recipe-range-slider-block-focus-ring` | `--poodle-recipe-slider-block-focus-ring` |
| `--poodle-recipe-range-slider-block-fallback-text` | none; no external fallback line exists |

Retained hooks: all fourteen remaining `--poodle-recipe-slider-*` hooks plus
`--poodle-recipe-range-slider-block-selected-fill`, `-block-selected-text`,
`-fill-fill`, `-fill-negative` and `-focus-ring`. The new
`--poodle-recipe-tabs-card-item-fill` hook was added.

### Breaking — Markdown preview is safe by default

| Surface | Change | Migration |
| --- | --- | --- |
| Svelte `MarkdownEditor.htmlPolicy` (new) | default `"safe"` | Editor preview and `MarkdownRenderer` sanitize the complete HTML result of the built-in `marked` path **and** of a custom `renderHtml` closure. |
| Svelte/React `MarkdownEditor.renderHtml` behavior | a custom renderer no longer bypasses sanitization | Pass `htmlPolicy="trusted"` for fully trusted content; there is no compatibility fallback. |
| `MarkdownEditor.renderHtml` prop type | inline closure type → named `MarkdownHtmlRenderer`, identical signature | No migration. |

### Breaking — Rust source/tag consumers

`poodle-specs`:

- `pub enum SliderAppearance` and its `pub use` re-export are removed; use
  `SliderVariant`. `SliderVariant::Standard` becomes the default `Block`
  (capsule), with `Embedded` for the dense control.
- `SliderSpec.appearance`, `SliderSpec::with_appearance`,
  `RangeSliderSpec.appearance`, `RangeSliderSpec.visible_range_text`,
  `RangeSliderSpec::with_visible_range_text` and `pub fn reject_vertical_block`
  are removed; `RangeSliderSpec::with_appearance` becomes `with_variant`.
- `TabDefinition.pinned` plus `with_pinned` and the new `TabPin` enum are
  additive in semantics but source-breaking for exhaustive struct literals; use
  the builder or add `pinned: None`.

`poodle-headless`:

- `slider_fallback_text`, `range_slider_fallback_text`,
  `default_visible_range_text` and `resolved_range_text` are removed.
- `default_visible_value_text(value)` becomes `(value, min, step)` and
  `resolved_visible_text(value, explicit)` becomes
  `(value, min, step, explicit)`; the output is a step-aware fixed-width decimal.
- `SliderBlockLayout { inline, fallback }` becomes
  `{ label_inline, value_inline }` and `RangeSliderBlockLayout { inline,
  fallback, selected_text }` becomes `{ label_inline, lower_inline,
  upper_inline }`. `layout_slider_block` / `layout_range_slider_block` lose
  their `selected_norm` / `lower_norm` / `upper_norm` / `range_text` parameters.
- `TabsItem` gains `pinned: Option<TabPin>`.

`poodle-node`: `NodeRole` gains `Banner`, `Heading` and `SearchBox`, and
`NodeA11y` gains `initial_focus: bool`.

`poodle-render`: `slider_block::block_grab` is removed (use
`block_grab_with_axis`), `block_surface(hit_px)` takes `cross_px`, and
`fraction_anchor` takes a trailing `layer_offset`. `pub use detail_item::…` grew
by `detail_item_with_slots_state`.

### Added — web editor entries

`@inflatable-cookie/poodle-svelte` and `@inflatable-cookie/poodle-react` add
`./editor`, `./editor/codemirror` and `./rich-text`, each with 25 new runtime
dependencies (`@codemirror/*`, `@lezer/highlight`, `@tiptap/*`). Existing
entries and every `peerDependencies` constraint are unchanged.

- `CodeEditor` — CodeMirror-backed, with a consumer-selected language registry,
  live line-number reconfiguration, real token-bound syntax presentation and the
  dual dark/light syntax palettes. Not part of the 176-name native roster.
- `RichTextEditor`, `RichTextRenderer` — TipTap/ProseMirror-backed, with toolbar
  projection/validation, configurable `Normal`/H1–H6 heading select, controlled
  echo selection preservation and an offline image-policy fixture. Web-only; no
  native counterpart.
- `MarkdownRenderer` — additive export inside the existing `./markdown` entry;
  web-only companion with no parity credit.

### Added — core, tokens and icons

- 91 new core root exports across the CodeEditor, rich-text, markdown, Slider
  family, Tabs, DOM/modality and icon families, plus `SliderVariant`,
  `SliderPolarity`, `TabPin` and `MarkdownHtmlPolicy` in `./types`.
- Ten `--poodle-color-syntax-*` custom properties in `poodle-tokens.css` and
  every theme artifact (30 declarations in the base file, 10 per theme).
- New `--poodle-md-renderer-*`, `--poodle-rich-text-*`,
  `--poodle-slider-family-*` and marker-position variables, and the
  `code-editor.css`, `rich-text.css` and `slider-family.css` stylesheet modules
  behind the existing `./styles/*` entry.
- Six icon registry identifiers: `between-horizontal-start`,
  `between-vertical-start`, `list-ordered`, `square-code`, `strikethrough`,
  `table`.

### Behavioral (same public shape)

| Area | Change | Basis |
| --- | --- | --- |
| Tabs card inactive fill | Every card item carries `background-surface`; inactive cards are surface-filled without a border. `activeFill="none"` keeps the variant's idle surface. | `docs/contracts/components/tabs.md` |
| Tabs reorder | New `pinned` partition law: pinned items are never reorder sources/targets; an unpinned item cannot cross a pinned partition; `items` must already be partition-ordered. | Same contract |
| Slider/RangeSlider normalization | Exact or out-of-range bound input resolves directly to `min`/`safeMax`, so both endpoints stay reachable when `step` does not divide the range evenly. | `docs/contracts/components/slider.md`, `range-slider.md` |
| Slider/RangeSlider display text | Default visible values round and zero-fill to the precision implied by `min` and a finite positive `step`, normalize negative zero, and never expose binary tails. | Same contracts |
| Slider/RangeSlider block text | One fixed whole-track layout for both selected and remainder layers; the optional label yields under narrow fit while the value never moves or disappears. | Same contracts |
| Select navigation | A non-searchable, non-freeform Select no longer filters its option list by the committed label, so keyboard navigation reaches every option. | `packages/core/src/select.ts` |
| Focus chrome modality | Select, TokenInput, NumberInput, DurationInput, FilterBuilder, OrderBy, MenuSurface and AgentChatInput install the input-modality observer; `:focus-within` chrome is gated by `:root[data-poodle-input-modality="keyboard"]`. | Component contracts and sources |

## Downstream checks

- Remove `appearance`, `variant="standard"`, `sliderFallbackText`,
  `rangeSliderFallbackText`, `defaultVisibleRangeText`,
  `resolveRangeVisibleRange` and `formatVisibleRange`; standardize on
  `variant="block" | "embedded"`.
- Rename consumer CSS hooks from `data-appearance` to `data-variant`, and move
  removed RangeSlider recipe hooks to their `--poodle-recipe-slider-*`
  successors.
- Set `htmlPolicy="trusted"` where raw markdown HTML is intentional.
- Update Rust exhaustive matches and struct literals for `SliderVariant`,
  `TabPin`, `TabsItem.pinned`, `NodeRole` and `NodeA11y.initial_focus`.
- Consume compiled package archives only after the separate certification and
  publication gates pass. React remains validation-only.

## Candidate boundary

This note records candidate intent. It does not authorize a tag, npm or
crates.io publication, GitHub release, workflow dispatch, registry mutation,
Jetstream admission, or windowed/native-visual validation.
