# 0.2.2 — 2026-08-24

`0.2.2` is a patch release that corrects a **public Rust dependency-identity
defect** shipped in `0.2.1`. It carries the same component, contract, token,
and renderer payload documented in the [full 0.2.0 release
notes](0.2.0.md). There are no product API changes in `0.2.2`, and no new
component behavior.

Consumers moving from `0.1.0` must still follow every breaking-change and
migration instruction in the [0.2.0 notes](0.2.0.md).

## The 0.2.1 defect

`0.2.1` resolved `gpui` from an `inflatable-cookie/zed` Git fork rather than
from crates.io. The fork existed to reach `HeadlessAppContext` and
`render_to_image`, which stock GPUI does not publish, so that an offscreen
pixel-capture tool could run.

That was an internal tooling need answered with a **public** dependency
change. A forked `gpui` is a different crate identity from the published one.
Longhorn adoption proved the consequence: a consumer that declares
`gpui = "0.2.2"` for itself gets GPUI types that are not the GPUI types
`poodle-gpui-node-backend` exposes, so ordinary calls across the boundary fail
to compile. No `[patch]` or `[replace]` can be called a fix here — the
released source shape was wrong.

The fork also carried GPL-3.0-or-later tracing crates out of the newer
unpublished GPUI revision, which is why the fork was narrowed rather than
adopted wholesale in the first place.

## What 0.2.2 fixes

- `poodle-gpui-node-backend` and `poodle-gpui-preview` resolve
  `gpui = "0.2.2"` from crates.io. The `inflatable-cookie/zed` fork and
  `gpui_platform` are gone from every active manifest and lockfile, and both
  Rust graphs resolve **zero** Git sources.
- A downstream crate that declares crates.io `gpui = "0.2.2"` for itself now
  compiles against Poodle's node backend and passes `AnyElement`, `Hsla`,
  `FocusHandle`, and `Bounds<Pixels>` across the boundary in both directions,
  with no override. `effigy drift:gpui-consumer-identity` runs this proof on
  the native board, including a negative control that must fail.
- Source policy is fail-closed on both layers: the repository security
  policy's approved-Git-revision allowlist is empty, `gpui` and
  `gpui_platform` are rejected from any Git source even if a repository is
  ever re-admitted, and `deny.toml` carries `allow-git = []` with
  `unknown-git = "deny"`.
- Inset box shadows are painted by the backend rather than by a fork-only
  `BoxShadow::inset` field, so Accordion, ActionDiscoveryPanel, ListCard,
  Popover, and Tabs keep the layers they declared. This is a renderer-internal
  mechanism change with no contract or API change.
- **The licence and notice surface matches the final graph.** `bzip2` and
  `libbz2-rs-sys` left both GPUI graphs with the fork, but the notices, the
  `deny.toml` allow list, and the spec still said they were present. That
  over-attribution was a false statement about what Poodle distributes, so the
  claims are removed. `packages/gpui/node-backend/THIRD_PARTY_NOTICES.md` held
  nothing but that notice and is deleted; the crate has no remaining
  third-party notice obligation. `audit:licenses` now enforces notice truth in
  **both** directions against the lockfiles — a missing notice fails, and so
  does a retained claim no lockfile resolves.

Full detail: [g16.005 GPUI crates.io
recovery](../logs/2026-08/20260823-g16-005-gpui-cratesio-recovery.md).

## Native evidence boundary — read this before believing a screenshot

Stock crates.io GPUI 0.2.2 has **no true offscreen pixel readback**. The
capability the fork provided is genuinely lost, and Poodle does not claim it
back under a different name.

- Default GPUI evidence stays on GPUI's **in-memory test platform**. It opens
  no window and needs no Screen Recording permission. `qa`, `ci`, `docs:check`,
  and every release gate run there.
- Real pixel capture is now an explicit **non-activating window-server
  diagnostic**, not headless rendering. `poodle-window-capture` opens one real
  GPUI window with `focus: false`, never activates the application, captures
  that window by its own window id, and refuses to publish if the frontmost
  application changed during the run. Its verdict is three-valued —
  `proved`, `changed`, `unprovable` — and only `proved` publishes.
- That diagnostic sits outside QA, CI, and every release gate. Its selectors
  carry a `-windowed` suffix and need explicit operator approval.
- Receipt schemas were renamed rather than reused: `renderer:
  "metal-headless"` became `transport:
  "macos-window-server-nonactivating"`, and `gpuiRevision: <sha>` became
  `gpuiSource: "crates.io"` + `gpuiVersion: "0.2.2"`. The verifier asserts
  `gpuiSource === "crates.io"`, because a receipt produced against a forked
  GPUI is not evidence about what a consumer gets.

## What publishes

| Package | Version | Disposition |
| --- | --- | --- |
| `@inflatable-cookie/poodle-core` | 0.2.2 | preview-channel npm package |
| `@inflatable-cookie/poodle-svelte` | 0.2.2 | preview-channel npm package |
| `@inflatable-cookie/poodle-react` | 0.2.2 | **experimental — packed and certified, not published** |

The two web packages carry no code change in this patch. They move so the
ecosystem version set stays aligned across one tag.

Rust crates remain source/tag distribution and carry `0.2.2` in lockstep.
They are not published to crates.io:

- contracts: `poodle-adapter`, `poodle-events`, `poodle-headless`, `poodle-ir`,
  `poodle-layout`, `poodle-markdown`, `poodle-node`, `poodle-specs`,
  `poodle-style`, and `poodle-tokens`;
- composition: `poodle-render`;
- backends: `poodle-gpui`, `poodle-gpui-node-backend`, and
  `poodle-jetstream`.

Jetstream remains program-deferred.

## Downstream checks

- **Rust consumers must upgrade.** `0.2.1` is unusable alongside crates.io
  GPUI. Move Poodle Rust Git dependencies to version `0.2.2` and tag `v0.2.2`
  together, then confirm `cargo tree -i gpui` resolves exactly one `gpui`
  from `registry+https://github.com/rust-lang/crates.io-index`.
- Web consumers install core and Svelte together at exactly `0.2.2`. Nothing
  else changes for them.
- Re-run the migration and behavioural checks listed in the [0.2.0 release
  notes](0.2.0.md) if you are still coming from `0.1.0`.
- Do not request `@inflatable-cookie/poodle-react` from npm; it remains
  source-only.
- Do not treat any Poodle GPUI screenshot as headless output. If you need
  pixels, run the operator-approved windowed diagnostic and read its
  foreground verdict.
- If you redistribute Poodle's Rust sources, drop the `bzip2`/`libbzip2`
  notice you may have copied from `0.2.1`. Poodle no longer depends on it, and
  Poodle's own notice surface no longer carries it.
