# 0.2.0 — 2026-08-23

The first release prepared against a frozen, measured denominator: **175 public
Svelte components**, every one of them carrying a contract, an implementation,
a package export, a preview specimen, focused tests, and packed-tarball import
proof. It follows the `0.1.0` registry release of Poodle core and Svelte;
React remains source-only.

Still pre-release. Breaking changes may occur in `0.x` and no `stable` channel
exists. See the
[versioning rules](../specs/022-packaging-versioning-and-release-channel-rules.md)
and [change-control rules](../specs/044-deprecation-change-control-and-release-channel-operations.md).

## What Publishes

| Package | Version | Disposition |
| --- | --- | --- |
| `@inflatable-cookie/poodle-core` | 0.2.0 | published to npm |
| `@inflatable-cookie/poodle-svelte` | 0.2.0 | published to npm |
| `@inflatable-cookie/poodle-react` | 0.2.0 | **experimental — packed and certified, not published** |

`@inflatable-cookie/poodle-core/tokens`, `/styles`, and `/icons` are subpath
exports of `@inflatable-cookie/poodle-core`, not separate packages. The
generated token and icon artifacts are committed, so a clean tarball is
complete with no build step: the `0.2.0` core pack carries 22 token
stylesheets covering the twelve themes plus the density and control-size
modes, and 108 icon modules. The twelve-theme set itself is unchanged since
`0.1.0`.

React is held to the same anatomy contracts as Svelte through the parity gate
and proves the same 175/175 packed root imports, but it has no downstream
consumer and no runtime-behaviour denominator of its own. It ships as source in
this repository and stays off the registry until it has one.

Rust crates are source/tag distribution, not registry publication. They carry
the same `0.2.0` version so one tag names the whole repository:

- Contracts: `poodle-adapter`, `poodle-events`, `poodle-headless`,
  `poodle-ir`, `poodle-layout`, `poodle-markdown`, `poodle-node`,
  `poodle-specs`, `poodle-style`, `poodle-tokens`
- Composition: `poodle-render` — the one Rust component tier, emitting
  `poodle-node` trees
- Backends: `poodle-gpui`, `poodle-gpui-node-backend`, `poodle-jetstream`

`poodle-codegen`, `poodle-gpui-preview`, and `poodle-jetstream-preview` remain
internal tooling. They are source-accessible, version-aligned for the tag, and
are not distribution targets.

## Evidence Posture

Each runtime reports its own evidence. No runtime borrows another's pass.

- **Svelte** — the release denominator. 175/175 on contract, implementation,
  export, specimen, focused test, and clean-tarball root import.
- **React** — 175/175 implementation, export, gallery specimen, focused test,
  and clean-tarball root import; anatomy parity is gated against Svelte.
  Runtime behaviour evidence is bounded to a representative mount set
  (9 Svelte, 13 React components), and import reachability is not presented as
  behaviour evidence.
- **Shared Rust (`poodle-render`) and GPUI** — 174/174 Rust declarations,
  174/174 Rust render modules, and 174/174 GPUI specimens against the
  denominator less `MeterSurface`, which is web-only by fixed decision
  (spec 068). Focused native regressions run mounted on GPUI's in-memory test
  platform; a headless specimen probe constructs all 174 portable catalogue
  routes.
- **GPUI accessibility** — GPUI exposes no platform accessibility attributes.
  Roles, names, and value ranges reach the renderer-neutral node and stop
  there. Nothing here claims otherwise.
- **Jetstream** — program-deferred. `poodle-jetstream` compiles against the
  shared contracts and is versioned with the tag, but Jetstream is not passing
  parity, is not part of the active cohort, and its deferral is not a
  per-component exception.

### Visual Comparison Boundary

Cross-runtime pixel comparison exists for exactly one primitive: Button, over
a frozen 18-fixture inventory captured through Svelte, React, and GPUI.
Svelte ↔ React is pixel-identical on all 18. Svelte ↔ GPUI passes the fixed
renderer-aware policy on geometry, fill, border, text, and pixels, with 16
annotated, contract-cited `gpui-omits-box-shadow` findings still reported and
still blocking in the comparator.

This is a diagnostic lane, not a release gate and not component authority. It
covers one component, on one machine, with same-host Metal rasterisation;
cross-machine determinism is not claimed. Nothing in this release asserts
visual parity beyond those 18 fixtures.

## Changes

### Breaking — web (`@inflatable-cookie/poodle-core`, `@inflatable-cookie/poodle-svelte`, `@inflatable-cookie/poodle-react`)

- **`Tabs` `variant` is three members, not six.** `TabVariant` is now
  `"card" | "pill" | "block"`. `"text"`, `"underline"`, and `"strip"` are gone.
  `"underline"` was never a distinct look — it aliased `"text"` and had no
  stylesheet rules of its own.

  `"card"` is a **reused name, not a preserved one**: the old `"card"` filled
  the tab chip, and the new `"card"` is the old `"text"`. Applying this table
  before upgrading will change how your tabs look.

  | Before | After |
  |---|---|
  | `variant="text"` | `variant="card" bordered` |
  | `variant="underline"` | `variant="card" bordered` |
  | `variant="strip"` | `variant="block" activeEdge="underline" activeFill="none"` |
  | `variant="card"` | `variant="card"` — appearance changed; see `bordered`, `activeEdge`, `activeFill` |
  | `variant="pill"`, `variant="block"` | unchanged |

  `TabStrip` is a separate component and is unaffected.
  **Downstream re-check:** every `Tabs` usage, plus any CSS selecting a removed
  `data-variant` value.

- **`Tabs` `bordered` now defaults to `false`.** This is a silent visual
  change: tabs rendered above a panel lose their separating line with no type
  or build error. The old default assumed "tabs above content", a layout Tabs
  cannot see, and every other usage paid for it in dead space.
  **Downstream re-check:** add `bordered` explicitly to any usage that draws
  tabs over content.

- **`Popover` interactive triggers are state-aware renders.** Composing a real
  Button or IconButton as a Popover trigger no longer forces a choice between
  nested interactive semantics and a missing disclosure relationship. In
  interactive mode (`triggerIsInteractive`) the trigger receives the
  core-authored `PopoverTriggerState` (`expanded`, `controls`, `disabled`):
  Svelte `trigger: Snippet<[PopoverTriggerState]>`, React
  `trigger: (state: PopoverTriggerState) => ReactNode`. The actual control owns
  `aria-expanded`, `aria-controls`, and the disabled state — in server output
  and hydrated DOM alike — while the wrapper stays a roleless, untabbable
  layout host. The old shape (a static node or zero-argument snippet beside
  `triggerIsInteractive`) is gone.

  **Migrate:** give every interactive trigger the state parameter and apply all
  three fields to the real control — `Button` takes `ariaExpanded` /
  `controls` / `disabled`, `IconButton` takes `expanded` / `controls` /
  `disabled`, a native button takes `aria-expanded` / `aria-controls` /
  `disabled`. React rejects the old shape at compile time. Svelte's
  discriminated snippet typing rejects a wrongly-typed payload and
  wrong-branch usage but **cannot** reject a zero-argument snippet
  (TypeScript function assignability), so Svelte migration must be enforced by
  search and review.

- **`Pill` `appearance` defaults to `"tint"`.** `PillAppearance` gains
  `"tint"`, and the implicit appearance moves from `"solid"` to `"tint"`.
  Default rendered output is unchanged; the emitted `data-appearance` value is
  not. Explicit `appearance="solid"` now resolves the opaque shared
  `solid_tone_surface` recipe rather than the former Pill-local treatment.
  **Downstream re-check:** CSS or tests asserting `[data-appearance="solid"]`
  on default pills, and the look of any explicit `appearance="solid"` pill.

- **`Icon` no longer takes `density`.** Icon size is decided by `size` or by
  the inherited presentation scale through `sizeRole`; a density input on a
  glyph had no contract behind it.
  **Downstream re-check:** remove `density` from direct `Icon` callers.

### Breaking — Rust (`poodle-specs`, `poodle-render`, `poodle-node`, backends)

Pre-1.0, operator-approved, no aliases and no silent fallbacks. Source
consumers of the crates must react; web package consumers are unaffected by
this section.

- **Presentation is a construction-time cascade.** Every public component
  renderer takes `ctx: &RenderContext<'_>` instead of
  `theme: &dyn ThemeProvider`. `poodle_render` re-exports `RenderContext`,
  `ui_presentation_provider`, and `SlotBuilder` at the crate root. Semantic
  spec inputs move from `ControlSize` / `ControlDensity` to `Option<…>`
  (default `None`); `with_size` / `with_density` keep their names and
  parameter types and store `Some`. Explicit size stays final — `sizeRole` maps
  inherited presentation scale only. Scoped host slots on `app_header`,
  `field`, `filter_toolbar`, `media_preview_with_content`, `page_header`, and
  `block_editor_with_children` take `SlotBuilder` instead of built `Node`s.
  **Migrate:** thread one `RenderContext` from the root, reach the theme via
  `ctx.theme()`, and return builders from host slots.

- **Native instance identity is caller-supplied.**
  `SegmentedControlSpec::new(instance_id, options)`,
  `ResizeHandleSpec::new(instance_id)`, and
  `SplitViewSpec::new(instance_id, orientation)` now require a stable native
  instance scope. `ResizeHandleSpec` no longer implements `Default`.
  **Migrate:** pass an owned, stable id per mounted instance.

- **`SegmentedControl` has its own option type.** `SegmentedControlOption`
  replaces `ChoiceOption` for this family and carries icon and icon-only
  presentation. `ChoiceOption` is unchanged for `Select`, `RadioGroup`,
  `CardRadioGroup`, and every other family. The web `SegmentedControlOption`
  interface is unchanged.

- **`PillSpec` loses `fill`.** `PillSpec::fill`, `with_fill`, and
  `is_solid_fill` are gone; `is_solid_appearance` replaces `is_solid_fill`.

- **`IconSpec` loses `density`; `EmptyStateSpec` loses `compact`.** `IconSize`
  expands to `Xs | Sm | Md | Lg | Xl` with a 1:1 `ControlSize` mapping.
  **Migrate:** `.with_compact(true)` becomes
  `.with_size(EmptyStateSize::Compact)`; update exhaustive `IconSize` matches.

- **`poodle_render::audio_specimens` no longer returns combined pages.** The
  twelve `pub fn <control>(theme)` functions are replaced by
  `AudioSpecimen::{examples, size, density}`, so hosts compose axis panes
  through their own layout instead of receiving a pre-appended matrix.

### Additive

- **42 new components**, taking the Svelte and React rosters from 133 to 175:
  AgentChatInput, AgentMessage, AgentPlan, AgentPlanRecord, AgentQuestion,
  AgentQuestionRecord, AgentSubagent, AgentTranscript, AudioMeter, AudioSwitch,
  ChangedFiles, DragNumberField, EnvelopeEditor, Fader, GainReductionMeter,
  HistoryCenter, Keyboard, Knob, LicenceActivation, LicenceSeats,
  LicenceStatus, MessageCenter, MeterSurface, ModMatrixGrid,
  ModelCatalogueEditor, ModelConnectionCard, ModelConnectionPicker,
  ModelConnectionSetup, ModelPicker, RefSelect, RemediationBanner,
  SettingsShell, StateTile, Stepper, ToolCall, ToolCallGroup, UpdateCenter,
  UpdateStatus, ValidationSummary, ValueReadout, WaveformDisplay, XYPad.
- **`Breadcrumbs` item icons.** `BreadcrumbItem` is a discriminated union so
  `iconOnly` cannot be authored without an icon: every crumb supports
  text-only, icon-plus-label, or accessible icon-only presentation. The icon
  and label share one anchor, button, or current-page span — one navigation
  target, one accessible name. Rust mirrors it with `with_icon` /
  `with_icon_only`; the truncation ellipsis never inherits icon presentation.
- **`Button` `controls`.** Rendered as `aria-controls` when non-null, with
  `ButtonSpec::controls` / `with_controls` in `poodle-specs` projected to
  `NodeA11y.controls` through the shared render path. Direct Rust `ButtonSpec`
  struct literals must initialize the new field; builder callers are
  source-compatible.
- **Shared `ToneFill = "tint" | "solid"`** with `fill` on `Callout` and
  `RemediationBanner`, plus matching Rust spec fields and builders.
- **`Tabs` selection decoration is two orthogonal axes.** `activeEdge`
  (`"none" | "outline" | "underline"`, default `"none"`) and `activeFill`
  (`"none" | "tint" | "solid"`, default `"tint"`) compose freely and replace
  the former per-variant treatments. `NavigationMenu` takes the same two props.
  Both types are defined once in
  [`docs/contracts/004-shared-control-types.md`](../contracts/004-shared-control-types.md).
- **`PopoverTriggerState`** is authored in `@inflatable-cookie/poodle-core` and
  re-exported from both web roots.
- **A reusable focus-ring channel** in `poodle-node`, projected out-of-flow by
  GPUI. `Button` and `Stepper` declare it instead of recolouring their borders,
  and `Stepper` accepts keyboard entry with no pointer prelude.
- **Additive node accessibility**: `NodeA11y.value_min` / `NodeA11y.value_max`,
  plus `SplitViewSpec::divider_instance_id()` and
  `poodle_render::resize_handle_focus_id`.

### Behavioral

- **`CallOutSpec::default()`** now matches the web and contract default
  (`Neutral` + `Tint`) instead of the incorrect implicit `Info` tone. Rust
  callers that relied on the old implicit tone must set `StatusTone::Info`
  explicitly. Web callers are unaffected.
- **Shared Rust render tree.** GPUI and Jetstream consume the same
  `poodle-node` output instead of maintaining duplicate component
  implementations, so there is one place a component's composition, token
  resolution, and interaction intent are decided. That removes a class of
  drift; it is not behavioural parity evidence. Each backend still owns
  materialisation, input, text, and drawing, and Jetstream's backend
  integration remains deferred and unproven.
- **GPUI `AgentTranscript`** owns a real tracked viewport with a detach latch
  and jump-to-bottom, rather than a static list.
- **GPUI `Stepper`** binds selection, re-run, and collapse to separate live
  controls. Native arrow / `Home` / `End` movement remains a recorded web-only
  delta.
- **Native accessibility naming** was audited across the Jetstream specimen
  catalogue.
- **Dependency licence posture.** GPUI resolves through an exact
  Poodle-owned Zed fork that removes GPL tracing crates from the normal
  dependency graph; Git sources are admitted fail-closed by reviewed URL and
  immutable revision.

### Fixed

- **`Tabs` drag was dead in WebKit hosts.** `draggable` and `dragstart` sat on
  the `__item` chip div wrapping the `__tab` button; WebKit does not initiate a
  native drag when the press target is a form control inside a draggable
  ancestor, so WKWebView (Tauri) hosts could not drag any tab. The drag source
  moved onto `.poodle-tabs__tab` itself (Svelte and React); drop-target
  handling stays on the item.
  **Downstream re-check:** consumers styling `[draggable]` on
  `.poodle-tabs__item` should target `.poodle-tabs__tab` instead.

## Migration Checklist

1. Rewrite every `Tabs` `variant` through the table above, then decide
   `bordered`, `activeEdge`, and `activeFill` explicitly.
2. Give every `triggerIsInteractive` Popover trigger the `PopoverTriggerState`
   parameter and apply `expanded`, `controls`, and `disabled` to the real
   control. Search Svelte call sites by hand — the compiler will not find them.
3. Drop `density` from direct `Icon` callers.
4. Re-check CSS and tests that assert `data-appearance` on default `Pill`s, and
   look at any explicit `appearance="solid"` pill.
5. Re-check CSS selecting `[draggable]` on `.poodle-tabs__item`.
6. Rust only: thread one `RenderContext`, supply instance ids to
   `SegmentedControlSpec`, `ResizeHandleSpec`, and `SplitViewSpec`, initialize
   `ButtonSpec::controls` in struct literals, and move off `PillSpec::fill`,
   `IconSpec::density`, `EmptyStateSpec::compact`, and the old
   `audio_specimens` free functions.

## Change class

Breaking (Tabs variant and `bordered` default, Popover interactive trigger,
Pill implicit appearance, Icon `density`, and the Rust presentation/identity
migrations) + additive (42 components, Breadcrumb item icons, Button
`controls`, `ToneFill`, Tabs decoration axes, focus-ring channel) + behavioral
(shared render tree, Callout default tone, GPUI transcript and stepper,
dependency licence posture) + fixed (WebKit tab drag).
