## What This Thread Was Doing

Poodle `v0.2.1` published core and Svelte successfully, but Longhorn adoption
then proved that its Rust GPUI packages exposed an `inflatable-cookie/zed`
fork identity incompatible with a consumer using crates.io GPUI 0.2.2.
`g16.005` restored exact crates.io GPUI 0.2.2, replaced the fork-only capture
tool with an honestly named non-activating window diagnostic, passed the
operator review, and merged as PR 73.

This worker prepares the exact `v0.2.2` recovery candidate. Execute `g16.006`
only: move the accepted release denominator from 0.2.1 to 0.2.2, document the
source-identity defect and corrected boundary, produce clean local packs, run
the complete supported headless board, and record reproducible evidence
against one candidate SHA. This is candidate assembly, not release execution.

## Why It Matters

Longhorn and every remaining g16 consumer lane are paused until Poodle has a
tag whose GPUI types are source-compatible with ordinary crates.io consumers.
The candidate must preserve the accepted component behavior and publication
set while correcting the public Rust dependency identity. A green run from a
different commit, a hidden fork, or a locally published package would not
solve the consumer failure.

The exact-SHA split matters. Versions, locks, generated stamps, release notes,
packs, gates, and the proposed tag must describe the same immutable candidate
tree. `g16.007` separately owns operator certification, tagging, and
publication after this PR is reviewed and merged.
