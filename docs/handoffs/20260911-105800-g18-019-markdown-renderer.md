## What This Thread Was Doing

Execute [`g18.019`](../roadmaps/g18/019-markdown-renderer.md). Add paired public
Svelte and React `MarkdownRenderer` components through the existing
`./markdown` entry and route `MarkdownEditor` preview through the same private
rendering path.

## Why It Matters

Consumers need semantic read-only Markdown without mounting editor chrome or
copying Poodle's parser and prose styling. The current editor preview also sends
built-in and custom-renderer HTML directly into the DOM without sanitization.

## Current State

Both editors call `marked.parse()` or `renderHtml()` inline and inject the
result. They share preview CSS but no private renderer. The public contract now
fixes `MarkdownRenderer`, safe-by-default output, explicit
`htmlPolicy="trusted"`, neutral empty output, deterministic SSR, and dedicated
specimen pages. This lane is independent of the active editor and Slider
repairs and is required before the held web-editor acceptance sweep.

## Boundaries

Follow g18.019 exactly. Sanitize the complete built-in or custom parser result
under the default policy. Trust exists only through the explicit prop. Reuse one
private path per framework and the existing `./markdown` boundary. Do not add a
second Markdown AST, expose parser internals, redesign editing, implement native
parity, mutate release state, or touch Desktop.

## Important Context

Safe and trusted output must be visually identical, so policy cannot be inferred
from presentation. A shallow tag regex is not an acceptable sanitizer. Bind
malformed, encoded, namespace, event-handler and unsafe-URL cases in SSR and
browser execution. Supplying `renderHtml` alone must remain safe.

## Suggested Next Move

Plant the paired adversarial sanitizer failures first, choose the smallest
deterministic SSR-safe sanitizer boundary, then extract the shared content path
before adding the public shells and specimens.

## Completion Protocol

Open one non-draft PR from the queue-owned branch. Prove exact-head paired
component, SSR, browser, security, package-install and specimen behavior; run
both package/preview builds, accessibility checks, Effigy docs QA and
`git diff --check`; then report `ready_for_review`. Never merge, resume release
work, publish, or mutate Desktop.
