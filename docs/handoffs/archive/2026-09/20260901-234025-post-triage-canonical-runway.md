## Objective

Turn the accepted September decision and translation packets into one current,
canonical g16 continuation map. Close stale status, distinguish ready work from
real serial gates, compile only the smallest honest cards, and expose the safe
parallel implementation frontier. This is a planning consolidation, not an
implementation or release lane.

## Why One Batch

Several independently reviewed packets landed together. Promoting each through
a separate front-door writer would create avoidable numbering, README, and
generation-index conflicts. One delegate owns the reconciliation PR; the
orchestrator retains exact-head review, merge, worker dispatch, and all external
repository or release authority.

## Required Outcome

Produce one PR that:

1. Corrects stale canonical status, especially `g16.036` and the September
   research/decision continuation posture.
2. Assigns non-colliding g16 card numbers from the current register.
3. Creates only bounded cards whose inputs and authorities are settled now.
   Each card must name its writable scope, exclusions, review oracle,
   validation, serial prerequisites, and whether it is implementation,
   benchmark, architecture, release, or external-repository work.
4. Leaves genuine blockers visibly blocked. The dedicated-lab bootstrap,
   visual tranche, citations rich-content prerequisite, release mutation, and
   Jetstream cross-repository work must not be made ready by prose alone.
5. Defines the ready frontier and the named serial edges so the orchestrator
   can dispatch independent cards in parallel after merge.
6. Updates only the necessary canonical front doors and disposition of
   consumed triage meaning. Preserve research dossiers and point-in-time
   packets as evidence; do not delete them merely because their outcome was
   promoted.

Prefer a small number of outcome-sized parent/cards over one card per bullet or
one giant umbrella implementation. Do not compile public APIs that the accepted
packets deliberately left gated.

## Ownership And Scope

This delegate may edit roadmap cards, architecture/contracts only where a
merged packet already settles the meaning, g16/front-door status, and one
planning log if the repository convention requires it. It must not edit
production source, tests, packages, workflows, release manifests, sibling
repositories, or the parity ledger's evidence cells.

Do not create worker handoffs in this PR. The orchestrator will review the
canonical cards, merge the planning batch, then create and dispatch worker
handoffs from the accepted ready frontier.

- Run `effigy docs:check` if the changed canonical surfaces require it;

- Run `git diff --check origin/main...HEAD`.

## Stop Conditions

Stop and return to the orchestrator if current main exposes a genuine product
choice not already settled by the named packets; numbering collides with a
live unmerged card; a proposed promotion would authorize a release, sibling
mutation, public API, native visual run, or Jetstream admission; or a ready
card cannot be bounded without new architecture.

No operator questions are expected. Prefer an honest blocked/gated row over
reopening settled choices or inventing missing authority.
