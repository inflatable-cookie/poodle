## Answer

The visual work is blocked by infrastructure ownership, not by missing Poodle
component code. Unblock it with one external bootstrap followed by closed,
purpose-specific adapter extensions. Do not widen the Button manifest into a
generic scene system.

## Serial Route

### VL-0 — repository authority

Create or identify the dedicated internal `poodle-conformance-lab` repository,
name its maintainer, and authorize its Button-only bootstrap. The repository is
not a Poodle package and Poodle never depends on it. Until this authority is
explicit, no lab worker is dispatched.

### VL-1 — Button MVP bootstrap

Implement the already accepted Button-only architecture:

- a dev-only Tauri controller using Longhorn contract 022 for opted-in Svelte
  and React webviews;
- one short-lived, non-activating GPUI process per fixture;
- closed Button adapter and 18-fixture manifest;
- exact 240×80 logical capture at 2× scale, frozen motion, two repeats;
- typed request/result/PNG receipts with immutable Poodle, Longhorn, GPUI,
  toolchain, font, viewport, foreground, focus, and permission provenance;
- unknown fixture IDs, adapters, paths, runtimes, or source versions fail
  before a window opens;
- no workflow, CI, daemon, public schema, or reverse dependency.

Acceptance is one complete Button run with agreeing repeats across Svelte,
React, and GPUI, clean process exit, non-activation proof, and sanitized review
bundle. Bootstrap success proves only the lab mechanism and Button coverage.

### VL-2A — icon-geometry extension

After VL-1, plan and land a separate closed `icon-geometry` adapter and
manifest revision. It accepts only the six `g16.049` candidate pairs and the
endpoint/midpoint/reverse/frozen/interruption/teardown states required by
`g16.051`. It inherits every provenance, repeat, foreground, non-activation,
and exact-window law. Completion unblocks `g16.051`; it does not admit a pair
or public IconMorph by itself.

### VL-2B — Nucleus V2 extension

After VL-1, plan and land a separate Nucleus capture adapter/manifest for the
actual Nucleus application or a Nucleus-owned integration harness. Nucleus
owns state seeding, data, callbacks, and M2 identity. The lab owns capture and
V2 receipts. Start with the first accepted bounded visual tranche, then extend
only through reviewed manifest revisions until all 29 cohort components are
covered. Generic Poodle fixtures cannot stand in for this consumer proof.

VL-2A and VL-2B may be developed in parallel only after VL-1 is accepted and
only when their adapter/manifest files do not overlap. Registry integration and
schema revision remain serial review points.

### VL-3 — evidence use

- Poodle `g16.051` consumes the accepted icon bundle and decides
  admit/revise/reject for each pair.
- The Nucleus programme consumes exact V2 bundles only alongside Poodle
  M1/A1/V1, external A2, and Nucleus M2.
- The lab never changes Poodle thresholds, contracts, ledger status, or known
  deltas. It returns evidence and findings.

## Review Oracle

| Invariant | Smallest counterexample | Required response |
| --- | --- | --- |
| Lab stays closed | arbitrary component/props payload | reject before launch |
| Capture is exact | desktop crop or foreground change | reject bundle |
| Native process is bounded | persistent GPUI sidecar | reject architecture |
| Bootstrap is not admission | Button MVP used for icon/Nucleus claim | keep downstream blocked |
| Consumer owns V2 state | Poodle seeds fake Nucleus data | reject receipt |
| Repeatability is real | two captures disagree | no frame picking/averaging |

## Validation Boundary

The lab repository owns its build, tests, hashes, receipt validation, and
capture commands. Poodle validates only imported sanitized receipts and docs.
No Poodle-local `*-windowed` or native-visual selector is authorized as a
substitute.
