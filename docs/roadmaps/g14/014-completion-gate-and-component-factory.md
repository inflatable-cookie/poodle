# g14.014 — Completion Gate And Component Factory

Status: blocked pending `g14.008` adopt
Depends on: `g14.009`–`g14.013`

## Outcome

Make the adopted pipeline the normal way to add a component. One command
creates the bounded authority/case/harness skeleton and a curated specimen
stub; one standing gate blocks incomplete runtime coverage.

## Scope

- Derive the component roster from source and contract authority.
- Provide an idempotent scaffold for the six component profiles.
- Require interface, web pair, shared Rust composition, cases, observations,
  a curated specimen, certified capabilities, and three passing active runtime rows.
  Report Jetstream separately as program-deferred.
- Consolidate old prop/callback/spec/registration gates behind the completion
  board where claims overlap. Keep specimen-documentation checks distinct from
  behavioural conformance.
- Document the Button-to-HistoryCenter recipe in component docs.

## Acceptance

- A newly scaffolded fixture fails completion until all required work lands.
- Missing registration, inert handler, stale generated artifact, missing case,
  or declared absence cannot pass.
- The scaffold generates no behaviour and no component-specific test logic.
- One component addition demonstrates the workflow without manual registry
  archaeology.
