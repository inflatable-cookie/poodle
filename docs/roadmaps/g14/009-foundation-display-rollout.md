# g14.009 — Foundation And Display Rollout

Status: retired — `g14.008` rejected the pilot mechanism
Superseded by: `g14.021`

## Outcome

Migrate the `display` profile and shared layout/foundation components to the
adopted interface/case/completion pipeline without replacing curated catalogue
specimens with exhaustive cases.

## Scope

Freeze the roster from the executable component inventory. Migrate in bounded
tranches, deleting replaced declarations and fixture copies per tranche. Fix
parity defects before marking a component complete. Do not widen the adopted
kernel without a recorded contract need.

## Acceptance

- Every rostered component passes active-cohort completion.
- No missing native registration, duplicate executable fixture, or redundant
  portable declaration remains in the migrated profile.
- Curated specimens stay useful; exhaustive cases remain a separate
  diagnostic projection.
- Tranche cost and defects are recorded; standing CI stays bounded.

## Stop Conditions

- A family requires new behaviour in the schema or component-specific runner
  code. Return to architecture rather than creating a second path.
