## The five decision questions (state without assuming the answer)

1. **Invocation shape.** Standalone CLI binary, Cargo build script
   (`build.rs`), or proc-macro? What does each cost in build coupling,
   incremental rebuild behaviour, CI reproducibility, and ability to run
   read-only?
2. **Determinism.** What makes emitted output byte-stable across machines and
   runs — ordering, formatting, float and string escaping, line endings,
   timestamps, absolute paths, map iteration order?
3. **Drift gating.** How are committed generated artifacts kept honest? What
   does a `--check` mode need to report to be actionable, and how does it
   fail?
4. **Diagnostics.** How does an emitter point a failure back at authored
   source rather than at generated output?
5. **Role, if any, for type-mirroring tools.** Given data-driven emission, is
   there any part of the job `ts-rs` or `schemars` genuinely serves — for
   example emitting a JSON Schema for the IR artifact itself, as distinct
   from the component surfaces?

## Case study 1 — `packages/tokens/scripts/build-tokens.ts` (primary case study)

One DTCG source (JSON under `packages/tokens/schema/`) emitting CSS, TS and
Rust into `packages/tokens/artifacts/{css,ts,rust}` plus a copy into
`packages/core/src/tokens/generated/`.

**Invocation shape.** Standalone script, no package entry, invoked through
Effigy selectors: `"tokens:build" = "bun packages/tokens/scripts/build-tokens.ts"`
(`tasks/effigy.tasks.toml:11`), `"audit:tokens" = "bun packages/tokens/scripts/build-tokens.ts --check"`
(`tasks/effigy.tasks.toml:17`). **Check mode is a CLI flag, not a separate
program**: `const checkOnly = process.argv.includes("--check")`
(`packages/tokens/scripts/build-tokens.ts:10`). The header comment states the
design intent: "`--check` compares what would be written against what is
committed instead of overwriting it, mirroring `scripts/build-default-icons.ts
--check`" (`.ts:6`) and "committing generated source is only safe when
something fails if the tree and the generator disagree" (`.ts:8-9`).

**Determinism guarantees.** All sources of ordering are fixed:
- Input files are sorted by name before load: `listJsonFiles` ends in `.sort()`
  (`.ts:92`); `loadDirectoryObject`/`loadNamedDirectory` merge in that order.
- `collectTokenEntries` walks `Object.entries(node)` in insertion order
  (`.ts:137-139`), which is source-file order after the sort — deterministic
  token path order.
- `resolveEntries` preserves input order (`entries.map`, `.ts:178`); its Map
  (`sourceByPath`, `cache`) is used for lookup only, never iterated for output.
- Mode objects iterate `Object.entries(schema.modes.themes)` etc. in
  `loadNamedDirectory` order (sorted). Deterministic.
- Serialization is `JSON.stringify(value, null, 2)` for TS/JSON artifacts
  (e.g. `.ts:483-485`); string literals via `jsString = JSON.stringify`
  (`.ts:229`) — locale-independent escaping.
- Rust float literals via `formatF32` (`.ts:684-687`): `n.toString()` plus
  `.0` suffix when integral — locale-independent, no exponential notation.
- Output contains no timestamps, no absolute paths, no random values. Headers
  are constant strings from `formatHeader` (`.ts:362-364`): `"Generated by
  packages/tokens/scripts/build-tokens.ts. Do not edit manually.\n"`.
- Line endings: template literals emit `\n`; `fs.writeFileSync` performs no
  translation (`.ts:240`). Cross-machine stability then depends only on git
  checkout filters, not the emitter.

**Check mode mechanics and failure output.**
- `writeFile` (`.ts:233-241`) routes to `compare` when `checkOnly`
  (`.ts:235-237`); `compare` (`.ts:243-251`) byte-compares against the
  committed file (`existing !== contents`, `.ts:250`) and records the
  repo-root-relative path in `drift`.
- `copyDir` (`.ts:253-267`) compares instead of copying in check mode
  (`.ts:262-265`); `syncSvelteTokenArtifacts` (`.ts:270-274`) skips the
  `rmSync` in check mode (`.ts:271`) so the svelte `generated/` mirror is
  compared, not destroyed, read-only.
- Failure is one uncaught `Error` at the end, listing every drifted path,
  deduped and sorted (`.ts:981-987`): `Generated token artifacts are stale:
  <path per line>`. Exit code 1 via the uncaught throw. Success prints
  `Verified … generated token artifacts` (`.ts:986`). Verified live: `bun
  packages/tokens/scripts/build-tokens.ts --check` at HEAD exits 1 and lists
  exactly the seven `rust/*` files (see the failure section below), and
  leaves `git status` clean — the mode is genuinely read-only.

**Where it writes.** `packages/tokens/artifacts/` (CSS per theme/density/
control-size, `ts/*`, `rust/*` incl. `rust/typed/*`), plus the svelte mirror
`packages/core/src/tokens/generated/{ts,css}` (`.ts:270-274`). All 35
`packages/tokens/artifacts/*` files and 25 `packages/core/src/tokens/generated/*`
files are committed [VF, `git ls-files`].

**Known blind spot (feeds the failure-mode table).** `writeFile` never
deletes: a committed artifact the generator no longer emits is never
compared, so `--check` cannot see a stale orphan. The svelte mirror is the
only place with delete-on-regenerate (`rmSync`, `.ts:271`), and the icons
script (below) is the only generator with explicit stale detection. [WI from
`.ts:233-251` vs `.ts:253-274`.]

## Case study 2 — `scripts/build-default-icons.ts`

Generates per-icon TS modules, `generated.ts`, `aliases.generated.ts`, and
SVG sets from `lucide-static/icon-nodes.json` gated by a pinned manifest.

**Invocation shape.** Same pattern: standalone script; `--check` flag
(`scripts/build-default-icons.ts:19`); selectors `"icons:build"` and
`"audit:icons"` (`.tasks.toml:12-13`).

**Determinism guarantees.** Source version is pinned and enforced: if
`lucidePackage.version !== manifest.lucideVersion` the script throws
(`.ts:42-44`) — a source-catalogue pin, stronger than any ordering fix.
Names are canonicalised and validated: uniqueness (`.ts:52`), sorted
canonical names (`.ts:55`), sorted aliases (`.ts:58`), alias targets exist
(`.ts:63`), catalogue membership (`.ts:67`). `supportedNames` is sorted
before iteration, so `expected` Map insertion order is fixed; output is
built from that order. SVGs carry a fixed license header embedding the
pinned version (`.ts:152`). No timestamps, no absolute paths.

**Check mode and failure output.** `stale` (files on disk not in `expected`,
`.ts:176-177`) is detected and deleted in write mode (`.ts:197`) or failed in
check mode; `drift` byte-compares every expected file (`.ts:179-185`). Both
are reported in one sorted, deduped path list under
`Default icon artifacts are stale:` (`.ts:187-192`), exit 1 via throw. This
is the repo's only generator with orphan/stale detection. [VF]

**Where it writes.** `packages/core/src/icons/` (`generated.ts`,
`aliases.generated.ts`, `icons/<name>.ts`), `packages/render/assets/icons/*.svg`,
`packages/gpui/preview/assets/icons/*.svg` (`.ts:25-29`, `.ts:170-173`).

## The live failure: `docs:check` rewrites committed artifacts; `audit:tokens` fails at HEAD

Both entries are recorded in `PAPERCUTS.md` (2026-08-11 entry; the two facts
share one entry). This section characterises mechanism, detection gap, and
prevention. It does not fix anything.

### Mechanism

**Fact A — committed state ≠ generator output, for exactly the `rust/*`
target.** Live verification at HEAD: `bun packages/tokens/scripts/build-tokens.ts --check`
exits 1 with

```
Generated token artifacts are stale:
packages/tokens/artifacts/rust/density.rs
packages/tokens/artifacts/rust/metadata.rs
packages/tokens/artifacts/rust/primitives.rs
packages/tokens/artifacts/rust/themes.rs
packages/tokens/artifacts/rust/typed/mod.rs
packages/tokens/artifacts/rust/typed/primitives.rs
packages/tokens/artifacts/rust/typed/semantic.rs
```

(7 files; CSS and TS targets match). The check run left `git status` empty
— the comparison mode is read-only [VF].

**Fact B — the divergence was introduced by commit `45caae82`**
("Format agent subagent contracts and generated Rust tokens", 2026-08-11
08:38), which touched 7 generated rust artifacts (plus two hand-written Rust
files) and did not touch `build-tokens.ts`. The diff direction is proven:
removed lines are exactly the generator's form — 4-space override-array
elements (`    ("color.background.canvas", "#f4eee3")`) replaced by
rustfmt's 8-space form in `themes.rs`, and single-line
`ColorValue(0.98…, 0.99…, 1.0, 1.0)` tuples replaced by rustfmt's
multi-line wrapping in `typed/primitives.rs`. The generator's
`buildRustDefinitionArray` emits the 4-space form
(`packages/tokens/scripts/build-tokens.ts:765-773`); its `formatColorConst`
emits the single-line form (`.ts:689-690`). `audit:tokens` was therefore
green at `45caae82^` and broke at `45caae82` [WI from the commit diff —
the removed lines are byte-identical to what the generator emits today].

**Fact C — the emitter's whitespace contract is single-source but
non-rustfmt.** All indentation and wrapping in `build-tokens.ts` comes from
its template literals (e.g. `.ts:770-773` for array elements, `.ts:689-690`
for color consts). Nothing in the generator runs or consults rustfmt; the
artifacts are compiled by the `poodle-tokens` crate through
`#[path = "../../../tokens/artifacts/rust/mod.rs"]` (card 003 R1 [VF]) and
are therefore subject to rustfmt-compatible expectations and to any
formatting tool that walks the tree.

**Fact D — `docs:check` composes the write-mode generator.** Selector chain,
verified: `docs:check` (:251-259) → `{ task = "report:parity" }` (:256) →
`{ task = "tokens:build" }` (:46) → `bun packages/tokens/scripts/build-tokens.ts`
(:11, no `--check`). In write mode `writeFile` unconditionally overwrites
(`.ts:239-240`). Since committed ≠ generated (Facts A+B), running
`docs:check` rewrites those seven files to generator form, leaving a dirty
worktree. The papercut records this as observed: "`effigy docs:check`
rewrites the committed `packages/tokens/artifacts/rust/*` … leaving a dirty
worktree" [SAC — recorded observation]. The mechanism is fully consistent
with the verified selector wiring and the verified byte divergence [WI].

### Why it went undetected

1. **A write-mode generator inside a gate cannot detect drift — it
   manufactures the expected state.** `docs:check` regenerates, so whatever
   the emitter produces becomes "correct" for that run; the tree is dirty but
   no check compares the pre-run state. The only symptom is a dirty worktree,
   and nothing in the gate consults `git status`. The repo even documents the
   intent ("something fails if the tree and the generator disagree",
   `.ts:8-9`) and provides the correct gate (`audit:tokens`), but the docs
   gate composes the wrong selector. [WI from Facts C/D + selector wiring]
2. **The check gate exists but lives outside the gate that broke.** 
   `audit:tokens` is in `ci:web` (`tasks/effigy.tasks.toml:197`) — a local
   contributor running `effigy docs:check` (the day-to-day gate) never hits
   it. The CI lane would have caught the commit, but the local gate is what
   agents run. [WI]
3. **The offending commit is a formatting-only commit, and hand-formatting
   generated files is not mechanically prevented.** The artifacts carry a
   "Do not edit manually" header (`.ts:362-364`) but the header is advisory;
   nothing rejects a diff that rewrites a generated file. A related papercut
   (2026-08-10) documents `cargo fmt --manifest-path` churn across linked
   workspaces — a plausible vector for the reformat — and `effigy doctor`
   reformatting generated artifacts (2026-08-10). [WI; papercuts recorded]
4. **Byte-exact comparison fails, but its diagnostic does not say why.** The
   `--check` error lists paths only (`.ts:983-984`); it cannot distinguish
   "content changed" from "formatting diverged", and it offers no diff. The
   failure is real (exit 1) but the resolution path ("align generator with
   committed formatting or regenerate") had to be derived by diffing the
   commit. [WI]
5. **The drift was introduced and recorded the same day.** `45caae82` is
   dated 2026-08-11 08:38; the papercut entry is dated 2026-08-11 — it was
   found by the next agent to run the gates, not by a gate failing at commit
   time. [VF — commit date vs papercut date]

### What an emitter design needs to prevent this

Each prevention is the smallest mechanism the failure demonstrates; none is
implemented here:

- **The gate must run check mode, not write mode.** The fix for the selector
  composition is to wire `audit:tokens` (or an equivalent `--check`) into
  `docs:check` instead of `report:parity`'s write-mode `tokens:build`. Spec
  063's Generated Artifact Contract already mandates the shape: "`ir:check`
  regenerates in isolation and fails on drift without rewriting the
  worktree." The tokens precedent violates it only in the composition, not
  in the tooling. [WI]
- **Canonical formatting must be owned by one authority.** The 45caae82 case
  is two formatters disagreeing: the emitter's string templates vs rustfmt's
  wrapping/indentation rules. Either the emitter emits rustfmt-identical
  bytes (owning every whitespace decision, as `formatF32` does for numbers,
  `.ts:684-687`) or the emitter runs the pinned formatter itself so that
  regenerated output == formatted output by construction. A drift gate with
  an unpinned formatter on either side is a flaky gate. [WI]
- **Write mode must be excluded from any gate that claims read-only
  semantics** — the failure existed only because `report:parity` (a writer)
  was embedded in `docs:check` (a gate). If writers and checkers are
  separate selectors, the gate can only compose checkers. [WI]
- **A committed-artifacts guard beyond a header.** The "do not edit
  manually" line is prose; the enforceable form is the check gate itself
  (which exists) plus it being on every gate path (which it is not), or a
  commit-time check that a generated file's diff is empty. [WI]
- **Diagnostics must separate content drift from formatting drift.** A
  `--check` that reports a per-file diff (or at least classifies "N bytes
  differ, all whitespace") turns a 45caae82-class commit from a mystery into
  a one-line fix. [WI]
- **Post-gate cleanliness as a last line of defence.** Any gate that does run
  writers can end with `git status --porcelain` empty — the cheapest
  detector of "a gate dirtied the tree". [WI]

Source: `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/schemars-1.2.2/`,

  artifact, and per-instance facts (a component's permitted subset) would

## Invocation-shape comparison

| Dimension | Standalone CLI (script or `[[bin]]`) | Cargo build script (`build.rs`) | Proc-macro |
|---|---|---|---|
| Build coupling | None — runs via Effigy/CI selectors; consumer crates pull generated files by `#[path]` (card 003 R1 [VF]); no Cargo dependency edge | Runs inside `cargo build` of the consuming crate; needs `OUT_DIR` plumbing and a runtime dependency edge | Runs inside `rustc`; macro crate must be a dependency of the authoring crate; affects the whole crate graph |
| Incremental behaviour | Only reruns when a selector is invoked; generated files only change when the generator or input changes | Cargo reruns on input/env fingerprint (`rerun-if-changed`); a slow generator stalls every consumer build | Re-runs per affected item when the macro crate changes; forces recompile of every downstream dependant of the macro |
| Read-only capability | Natural: `--check` flag already proven in-repo (`.ts:10`, icons `.ts:19`); verified exit-1-without-writing | Awkward: build scripts are expected to write `OUT_DIR`; a check mode needs a separate path or env switch, and `cargo build` cannot fail-read-only cleanly | No: proc-macros cannot write at compile time (ts-rs docs [SAC]); "read-only" is the only mode, output must be runtime/test-time |
| CI reproducibility | Full — deterministic inputs verified (sorted loads `.ts:92`, pinned source version icons `.ts:42-44`); committed artifacts compared byte-exact | Depends on Cargo's fingerprinting; `OUT_DIR` not committed, so CI must regenerate rather than compare | Deterministic output per compiler version, but generated output is never committed, so drift gating reduces to compile success |
| Diagnostic quality | In-repo precedent: check mode lists every drifted path, exit 1 (`.ts:981-987`, icons `.ts:187-192`); drift gates report all findings at once | Errors surface as build failures; pointing at authored source requires the build script to format its own errors | Compile errors can span macro expansion; pointing at authored source requires careful `Span` work (schemars/serde do this); ts-rs export failures are test failures |
| Observed in-repo precedent | **The only shape in use**: `tokens:build`/`audit:tokens`, `icons:build`/`audit:icons`, all five drift gates, all three report generators — all standalone scripts [VF] | None — zero `build.rs` files in the repo (verified by `git ls-files '**/build.rs'`) | None in this repo; both vendored crates are proc-macro-based and unevaluated for in-repo use |

No recommendation is made from this table; it records what exists and what
each shape costs.

| 2 | Gate composes write-mode generator, so drift is invisible | `docs:check` → `report:parity` → `tokens:build` (write) (Fact D) | Rule: gates compose only `*:check`/`audit:*` selectors; or cheapest mechanical guard — gate ends with `git status --porcelain` empty |

## Unresolved questions and unevaluated candidates

- **`typeshare`** — unevaluated, not vendored. Recorded for the orchestrator.
- **`specta`** — unevaluated, not vendored. Recorded for the orchestrator.
- **Formatting authority for `poodle-codegen` output.** The tokens case shows
  byte stability requires a single owner of whitespace; whether that owner is
  the emitter itself or a pinned `rustfmt` is an open design decision this
  evidence informs but does not settle.
- **`--check` diagnostic depth.** The in-repo precedent reports paths only.
  Whether IR's check should emit diffs (and how, without a diff dependency)
  is open.
- **Report-artifact gating posture.** The three report generators have no
  check mode; whether they should be gated like tokens or treated as
  non-gated derived docs is a policy question for the orchestrator.
- **`schemars` value-driven schema for IR evidence.** `root_schema_for_value`
  exists and is documented as less precise for enums (SAC); whether the IR
  artifact schema should be type-derived (derive) or value-derived
  (per-instance evidence) is a Q5 consequence the orchestrator rules.
- **Stale-orphan policy for committed generated files** (failure mode 5): the
  repo has the pattern in icons; extending it to tokens is mechanical but is
  a scope decision.
